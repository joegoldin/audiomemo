## The two experiences

1. **Quick Scribe:** from any application, press a shortcut, speak, press again. A click-through, non-activating caption appears at the bottom center of the invoking display, above the dock/panel. Show at most two lines over a translucent, contrast-preserving plate; tentative words can revise, committed words do not flicker. The panel disappears on finish, cancel, or failure. Copy the final text once by default; auto-paste is opt-in. Cancel does not touch clipboard or focus. Quick Scribe is mic-only, local-only, and does not save audio, transcript, or content-bearing logs. A last result may live in memory until replaced, cleared, or quit. Do not change the existing `scribe` command's transcript-saving behavior.
2. **Meetings:** one tray/menu action or bound CLI shortcut records the selected group without a terminal. Keep one original source track per unique input, an aligned merged listening track, a transcript, and a versioned manifest, all in one directory under the configured recording folder. Retain them all until the user removes them. The icon shows recording and elapsed time; Stop immediately ends capture, not after a model finishes. Signal source loss visibly and preserve what was captured. Finishing/retrying a job must never replace the only copy of a source. Meeting audio and transcripts stay local, even if the normal CLI is configured for ElevenLabs fallback.

**Hosts:** elphael is x86_64 NixOS, KDE Plasma/Wayland, PipeWire, MOTU M2 (`mic`, `speakers`, `combo`). Torrent is Apple Silicon macOS, with `mic` mapped to the built-in MacBook mic; AudioMemo already has a native Core Audio system tap. See the user's dotfiles `modules/hosts/{elphael,torrent}/_packages/audiomemo.nix` and `modules/home/packages/audiomemo.nix` (configuration examples only). A daemon is optional; existing commands must work without a daemon, without a display, and over SSH. Out of scope: Windows desktop, silent login enablement, automatic call recording/detection, calendar, LLM notes, live typing inside target fields, active speaker identification by name, cloud fallback for the new modes, and live machine rollout. Do not introduce a hidden always-open mic to win a latency benchmark.

## Contracts to freeze before parallel writers

### Selection and attribution

Add an optional `[device_roles]` table alongside `[devices]` / `[device_groups]`, e.g. `mic = "us"`, `speakers = "them"`. `auto` removes the explicit setting. The device browser and `audiomemo device role <alias-or-raw> auto|us|them` edit the same config. Give unaliased devices a stable raw-key representation; reject ambiguous keys/conflicting explicit roles for aliases resolving to the same device with a precise fix. Resolve in deterministic group order, deduplicate physical devices, freeze assignments in the manifest before capture. Roles belong to endpoints, never to a group as a whole. Show `Us (explicit)`, `Them (system audio)`, etc., beside members before recording. No obligatory migration or config rewrite on read.

Precedence: explicit override; monitor/native system audio → Them; configured single default mic → Us; if no usable single configured default (including a default group), the selected OS default mic → Us; otherwise Them. Never promote the first group member merely because it is first. When the OS default is unknown, do not guess from a display name. Preserve the reason and report missing/ambiguous hardware rather than silently substituting an unrelated mic. Quick Scribe chooses an explicit mic or a resolved Us microphone, never the default group's whole room/system mix. If no unambiguous mic is available, explain how to select one. A meeting requires explicitly configured or selected inputs; if there is no meeting group configured, offer selection, not silent capture of every output. An opt-in desktop config should allow selecting the existing `combo` on elphael and a mic + `system-audio` group on torrent.

Roles are **source provenance**, not a biometric claim. Keep `track_id`, resolved `role` (`us|them`) and optional track-local `speaker` independent on turns/words; two tracks' `speaker_0` are not one person. `Us` can cover two local people; `Them` can cover multiple remote speakers. Preserve overlapping turns and unassigned words. Do not label mixed-track recognition as Us/Them by guessing from a speaker number. Headphones are the reliable baseline; for speakers, flag possible bleed/ambiguous attribution rather than irrevocably dropping audio or claiming echo separation. Advanced echo suppression is follow-up work, not a substitute for testing double-talk.

### Capture, bundle and state

Proposed v1 layout: `<output>/meetings/<unique-id>/{manifest.json,tracks/001.wav,tracks/002.wav,mix.<format>,transcript.json,transcript.txt}`. Other exports use existing SRT/VTT formatting when requested. Paths in manifest are relative to the bundle; no path components from device names, titles, IPC arguments, or untrusted manifest fields. Create directories 0700/files 0600. Write derived artifacts to temporary siblings, then atomically publish; do not overwrite user edits silently. No automatic deletion of sources. Support long meetings beyond the classic WAV 4 GiB limit (RF64 or documented numbered lossless segments linked in manifest). Do not call a resampled/downmixed mix an original; document each track's captured format and any necessary normalization.

Manifest v1 minimally records id, schema version, capture/finalization state, timestamps/duration, selected group, ordered tracks (stable ID, endpoint identity at start, role/reason, sample rate/channels, files, start offset, gap intervals, errors), mix/transcript paths and independent job outcomes. Example: `002`, role `them`, offset `120 ms`, gap `[2100,2600) ms` means resume on the meeting timeline, not half a second early. Use monotonic timing and sample positions, not wall-clock arrival per packet. Specify a testable drift bound and strategies for different source clocks in lane 0. Keep originals and gap metadata; align and silence-pad derived outputs. `capturing → captured/interrupted → finalizing → ready/partial/failed`. A live capture has a single owner; retries operate only on closed bundles, never the live file descriptors. Recover an interrupted bundle on demand; do not pretend a crashed process captured until the time it restarted. If no source ever opens, fail explicitly. If only a subset opens or one stops, keep the good track and visibly identify the missing one.

### Daemon, CLI and desktop boundary

Foreground `audiomemo daemon` is supervised by a user service, never double-forks. One capture at a time; starting Quick Scribe during a meeting returns `busy`, never stops the meeting. A meeting start during dictation must likewise not discard it. Serialise expensive final work and bound queues; stop waits for source closure/durable manifest, **not** for merge or ASR. A queued previous job cannot change the active session's indicator; expose current capture and background job separately. Optional future warm-model reuse requires a measured benefit; the microphone is closed when idle. Bound Quick Scribe's retained PCM explicitly; on reaching its budget, finalize with a visible reason, never silently drop the opening or grow without bound. Meetings stream to disk; their duration is not bounded by RAM.

New control surface (spellings for workers to share):

| Invocation | Success contract |
|---|---|
| `audiomemo daemon` / `audiomemo status [--json]` | Foreground server, diagnostics on stderr / single state snapshot. Status never starts the daemon or opens audio. |
| `audiomemo dictate start\|stop\|toggle\|cancel` | Control Quick Scribe. Start/stop are idempotent; toggle is one edge. No unsolicited transcript on stdout of a control command. |
| `audiomemo meeting start [-D group]` | Return meeting ID after capture admission; clearly distinguish pending readiness from recording. No auto-upload. |
| `audiomemo meeting stop [--wait] [--print path\|text\|none]` | Default: durable bundle path as one stdout line. `--print text` implies wait for final; on failure nonzero, reason and recovery path on stderr, no misleading final text. `--wait` pins the stopped job ID, not the next meeting. |
| `audiomemo meeting retry <bundle>` | Validate and rebuild missing/failed derived artifacts from originals; repeated retry is safe. Never delete or truncate originals. |

A disabled/unavailable daemon is a clear nonzero error for controls. No implicit GUI startup from a pipe. Decide exact no-active-meeting stop result in lane 0 (recommended: nonzero/no stdout when there is no bundle to print). Keep existing generic failure status 1 unless a new documented code has a consumer. New daemon IPC is **not** `record --stream`. Version it independently: local Unix socket under private runtime dir; macOS private per-user equivalent; validate owner/permissions and connected peer, bounded frames/deadlines and subscribers, no network listener for desktop controls. Commands carry explicit session/job IDs internally. Coalesce **preview** snapshots, not final results. Client disconnect/slow overlay cannot stop capture. SIGINT to a waiting client cancels its wait, not someone else's meeting; SIGTERM to the daemon stops capture and leaves recoverable data. Front ends issue only these same actions. No control command supplied by a client executes arbitrary shell or paths.

Opt-in Home Manager config: `programs.audiomemo.desktop.enable`; login startup separately opt-in, off by default. Visible menus: Start/Stop meeting, Start/Stop Quick Scribe, Copy last result, status and Quit. Desktop delivery defaults to copy; optional paste only if the original target is still known and focused; otherwise copy and explain. If reliable focus identity isn't available (especially KDE Wayland), do not synthesize paste based on a guess. Don't send Return. If delivering via a temporary clipboard, restore only if neither user nor a later operation changed it; plain Copy intentionally leaves the result there. Clipboard managers can retain copies; do not promise ephemeral text after copying. Keep secrets, transcript content and PCM out of argv, logs, notifications, tests' real home and the Nix store. A tray-less/no-display process still supports headless control; don't start an invisible desktop meeting from a gesture with no working recording indicator.
